2) Core insight — Write ≠ Detect ≠ Localize

This run is the teaching trap for SLOWDOWN. There is no Maintain stage in the Datadog hub pipeline. Continuous telemetry is stage 03 Write (M ∥ APM ∥ Logs). Foghorns are stage 05 Detect (Door A Monitors ∥ Door B Watchdog). Leaf claims are stage 07 Localize.

StageJobThis Observed run

05 Detect · Door A Monitor query crosses threshold → Alert No — error-rate monitor 310925690 OK; no latency monitor defined
05 Detect · Door B Watchdog opens an anomaly story without that query No — 0 APM Watchdog stories (deployment version story ≠ latency RCA)
07 Localize Read flamegraph / longest self-time leaf Yes — but operator-driven — lab opened APM for the known fault window
08 Package Bits / Incident Incident 0 — Bits only if you start an Investigation (peer tab)

What Datadog did not do

From Detect’s point of view, nothing was declared wrong. No latency Door A Alert, error Door A stayed OK (correct for HTTP 200), Watchdog did not foghorn inventory latency, and no Incident was opened. Datadog did not Detect this case on stage 05.

What the data still showed

From the stores’ point of view, the slowdown was obvious if anyone looked: Metrics p95 jumped ~1000×, Trace Explorer fills with status:ok @duration:>5s, Service Map still shows FE→product→inventory peers. Explorers looking “hot” are reading 03 Write — that is not the same as a Door opening.

Who actually “detected and analyzed”

We did — the lab operator (and MCP pull), because we injected the fault and explicitly queried APM for env:rca-lab-e3 · version:slowdown-20260811t045553z · 04:58:07Z–05:10:34Z. We did not flip a Datadog UI switch that “marked this as an incident.” We opened explorers, sorted by duration, opened trace 6a7aabea…, and applied the SLOWDOWN leaf rule: longest / deepest self-time span (inventory.stock), not status:error (there is none).

3) Detect configuration (what you need for this lab)

Unlike ERROR (where auto Flask High Error Rate 310925690 Alerted after sustain), SLOWDOWN does not trip error-rate Detect. To get a Door A alert you need a scoped latency monitor, e.g. avg(last_5m):p95:trace.flask.request{env:rca-lab-e3,service:inventory} with avg/max/p95 (not min(last_15m)). This Observed run did not require that monitor — duration on traces was enough to teach the leaf after we opened APM.
