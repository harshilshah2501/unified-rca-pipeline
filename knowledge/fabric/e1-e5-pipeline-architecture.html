ObserveOps · E1–E5 fabric

E1 → E2 branches into Pillar A & Pillar B

Always-on fabric after ingest: optional Edge and Gateway shape telemetry before the Platform control plane runs E1 Collect through E5 Maintain. E2 Identity binds signals to stable configuration items, then the resolved stream fans out in parallel — Pillar B topology (E3 → map/) and Pillar A sketches (E4 → history/). E5 refreshes seasonal baselines into Pillar A. See shift-left locus map.

E1 Collect
Platform admission point: receives the shaped stream from Edge (optionally via Gateway) over TLS. E1 validates wire format and buffers — it does not bind CIs (that is E2).
input ← shaped MELT from Edge · output → ingest.v1 batch
E2 Identity
Binds collected signals to stable configuration items: identity matching, canonicalization, and identity.status (sketch writers admit resolved only). The resolved stream is the fan-out point — it feeds both pillars in parallel. Neither pillar sits inside Identity.
output → resolved identity stream (branched)
E3 · Pillar B Topology
Builds the relationship map from resolved configuration items — typed edges, hierarchy, provenance. Writes graph_node.v1 / graph_edge.v1 as a GraphSnapshot under map/. Does not write metric sketches.
output → map/ (GraphSnapshot)
E4 · Pillar A Stores sketches
Writes compressed metric history for one entity + window: T-Digest + buckets + seasonal baseline in one sketch.v1 row. Same tenant + entity_id (= ci_id) as the graph — but sketches never carry edges. Receives seasonal baseline refresh from E5. Writes to history/.
output → history/ (sketch.v1 store)
E5 Baseline refresh (Maintain)
Periodic sidecar. The dashed link on this diagram is seasonal baseline re-anchor into Pillar A (expected p50/p95/p99 for each season_key so Detect can compare digest vs season). Broader Maintain also covers graph validity / decay on the Pillar B map; that path is not drawn here so the fan-out stays readable.
feeds → E4 seasonal baselines (shown) · map validity (off diagram) · cadence: periodic
Three zones, one pipeline. Edge (Node / OTel) shapes telemetry before egress; Gateway is optional consolidation; Platform runs E1–E5 on our SaaS control plane. E2 Identity is the branch point inside Platform: resolved stream feeds Pillar B (E3 → map/) and Pillar A (E4 → history/ / sketch.v1) in parallel. Exemplars (optional) are captured at E4, not at Edge or E2. E5’s dashed link is seasonal baseline refresh into Pillar A.
