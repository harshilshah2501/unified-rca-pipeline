2 · Workflow — fabric vs case path

Always-on fabric (E1–E5) Keeps GraphSnapshot under map/ and sketch.v1 rows under history/ warm. Writers do not sync folders — they share join keys only (tenant + ci_id).
Case path (E6–E11) Opens when Detect fires. Reads fabric; does not re-collect the estate or rewrite topology per alert. Emits Signal → CaseSeed → WorkingSet → LeafClaim → EvidenceBundle → VerdictCard.
  • CI tip on Signal = the ci_id whose detector fired (identity already on the series from E2), not NLP on the alert title.
  • t0 = observation / event time of that Detect decision.
  • CaseSeed = one merged tip (ci_id, t0) + merge rationale — not the full neighborhood.
  • WorkingSet = window around t0 + suspects + k-hop neighborhood + sketch snippets + evidence budgets.
  • Follow the map (usual) — Localize walks authoritative edges (depends_on, runs_on, …) toward the leaf the Detect class expects; Identify attaches sketch percentiles and edge provenance.
  • Evidence can override — if sketches or corroborating edges contradict the first walk, Identify lowers confidence or revises the leaf; fabric stays, case objects change.
  • Verify is judgment inside Identify through Package — not a twelfth E-stage.

4 · GraphWriter — Topology writer (condensed)

Pillar B orchestrator under pillar-ab-implementation/pillar-b/poc. GraphWriter is an orchestrator, not a network service: lab CLI (or a future Topology worker) feeds it. It is the only node that writes map/. SketchWriter is a sibling on the same post-E2 stream, not an input to GraphWriter. Sketches never carry edges; the join is at WorkingSet read time.

InputPost-E2 ingest.v1 with fact_kind=topo_update (plus optional topology seed)

Three output actions

ActionMeaningExamples
WRITEAdmit — mutates GraphState, later flush publishes map/Valid topo_update with resolved identity and catalog relation
NOOPSilent skip — wrong class for GraphWriter; no state change, no reject codemetric_sample, event, trace_span, anomaly (Pillar A sketches are metrics-only)
DROPReject — looked like topo work but failed a rule; map unchanged; reason on writer.rejectsUnresolved identity, unknown CI type, illegal relation, policy fail

Phased (wave-1) skip of a catalog relation is map-NOOP (no write) but is not silent skip: the line was Topology’s job; it usually is not a DROP reason. Normative I/O: E2_INPUT_FIXTURES.md · MAP_WRITE_READ_RECORD.md · IDENTIFIED_STREAM_REJECT.md.

5 · Diagnose — present map vs history

Rooms, not one store. Scope read-joins neighbors from map/ with sketch windows from history/. Do not ask Topology for “what was p99 yesterday,” and do not ask sketch-history to rebuild the whole dependency graph.

QuestionRoomNot this
Who is this CI now?map/ nodesketch-history
What does it depend on now?map/ outbound edgestime series
Who fails if it fails now?map/ reverse walksketches
Worse than baseline around t0?history/ sketch rows for that ci_idtopology edges
Recent deploy / change?Change evidence (separate)sketch rows as topology

Checkout teaching spine (How, condensed)

Detect → Identify CI → Upstream (map) → History (sketches) → Blast → Localize → Package

StepHow (operator / implementer reading)
1 · DetectRead detector fields (service / CI, severity, t0, measured value). Tip = breached CI. Hand off to Curate before Scope. No root claim yet.
2 · Identify CILoad seed CI from present GraphSnapshot under map/ — not from sketch-history. Confirm type and aliases.
3 · UpstreamBounded outbound walk (depends_on, runs_on, …) into WorkingSet neighborhood. Still no latency numbers here.
4 · HistoryFor seed + blocking neighbors, fetch sketch.v1 rows for the alert window (percentiles / baselines).
5 · BlastReverse walk inbound edges for blast radius and stakeholders (Package narrative).
6 · LocalizeOne LeafClaim: deepest / longest-supported fault on the scoped neighborhood, not the noisiest alert.
7 · PackageEvidenceBundle pointers → VerdictCard (suspect, neighborhood, confidence, recommended action).
