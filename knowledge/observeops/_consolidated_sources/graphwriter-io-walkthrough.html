GraphWriter — who it talks to, and a concrete example

Walkthrough for the Pillar B Topology orchestrator under pillar-ab-implementation/pillar-b/poc. Input: post-E2 ingest.v1 with fact_kind=topo_update (plus optional estate bootstrap). Output: Gate B files.v1 under map/. OneOps / Fusion HTML briefs under archived-docs/ are catalog material only — they are not GraphWriter callers. Hub URL: :8765/graphwriter-io-walkthrough.html.

1 · Who

Partners GraphWriter talks to

GraphWriter is an orchestrator, not a network service. It is called by the lab CLI (or a future Topology worker). It reads optional bootstrap + ingest, writes Dest map/, and optionally runs the E5 maintain stub.
PartnerRoleWhat is exchanged
E1 Collect (upstream) Does not talk to GraphWriter directly Produces raw signals. Pillar B PoC never implements Collect; lab fixtures already look like post-Identity lines.
E2 Identity (upstream) Stamps identity on ingest.v1 GraphWriter only admits identity.status = resolved. Unresolved / synthesized lines become rejects.
Shared ingest stream Same wire as Pillar A JSONL of ingest.v1. GraphWriter filters fact_kind = topo_update; metric_sample, event, trace_span, anomaly are silent NOOP.
topology.bootstrap.json (lab) Optional bootstrap load_bootstrap fills GraphState with declared nodes/edges before the stream runs.
ResolvedOnlyGate (ab_shared) Shared identity admit Same gate Pillar A uses. GraphWriter does not invent a second identity policy.
ci_qualify + edge_catalog Catalog checks inside GraphWriter May this ci_type be a vertex? Is relation in the fifteen-name catalog (or wave-1 skip)?
Dest / FileDest (Gate B) Publish target flush → Dest.put("map", …) → graph_snapshot.json, nodes.jsonl, edges.jsonl under poc/out/<tenant>/map/.
Pillar A SketchWriter Sibling, not a caller Parallel writer on the same stream. No A∪B merge. Later diagnose read-joins by tenant + ci_id.
Diagnose / neighbors (downstream) Readers of map/ load_snapshot + neighbors walk the published graph. GraphWriter does not call Diagnose.
E5 maintain stub Optional after flush maintain_validity expires edges / drops stale corroborating; then republish a new snapshot version.

4 · Admit

Three output actions · NOOP · WRITE · DROP

Every ingest.v1 line ends in one of three GraphWriter actions. NOOP (silent skip) ignores the line; WRITE (admit) mutates GraphState; DROP (reject) records a shared reason code and leaves the map unchanged.

Decision diagram

A · NOOP

Silent skip. Wrong fact_kind for GraphWriter. No state change, no reject code. Examples: metric_sample, event, trace_span, anomaly (Pillar A sketches are metrics-only; logs/traces are not sketch.v1).

B · WRITE

Admit. Line becomes topology work: upsert CI node(s) and typed edge in GraphState; later flush publishes map/.

C · DROP

Reject. Looked like topo work but failed a rule. Map unchanged; reason on writer.rejects (shared codes).

5 · Build

Seed + stream → GraphState

OrderGraphWriter APIWhat it does
1 load_bootstrap(topology.bootstrap.json) Creates GraphState. Qualifies each bootstrap CI type. Declared bootstrap edges get evidence_type declared, telemetry_source topology.bootstrap.
2 ingest(JsonlIngestSource) For each topo_update: identity gate → ci_qualify → classify_relation → ensure endpoint nodes → upsert edge with provenance from identity.bind_source.
3 flush(FileDest) build_snapshot(version) validates packaged graph_snapshot.v1, then publish_snapshot writes the three map keys (overwrite).
4 maintain_validity (optional) E5 stub: expire valid_to / drop stale corroborating; flush again with a new version (lab CLI --maintain-validity).
Internal helpers (not separate services)

graph_builder.apply_topo_updates · ci_qualify.may_emit_vertex · edge_catalog.classify_relation · provenance.build_discovered_via · snapshot.build_snapshot / publish_snapshot · maintain.maintain_graph_validity
