ObserveOps — shift-processing-left architecture

This is our pipeline, not a vendor map. Same HLD stage model (E1→E11). What changes is where stages execute: Node / optional Gateway before egress, then our SaaS control plane. AI stays optional (HLD D5 Review / Layer I).

Scope: multi-tenant product · full MELT + events + profiles · K8s and VMs · destination-agnostic fan-out · Detect on both doors (edge + platform).

2. E1–E11 stage locus map

Same HLD clock as Our HLD. Shift-left does not add stages. It only changes where each stage’s work runs. Node is +1 hop. Optional Gateway is +2. Contracts (purpose, I/O objects) stay E1→E11.

Read the columns as a split, not a move: a stage can start on the Node and still have a SaaS half (E3 graph persist, E6 door C, E5 config push). Gateway omitted ≠ stage omitted — door B and Gateway-side E3 assist simply do not run.

Normalize = E2 Identity (not a 12th stage, not E10). Verify is decided in E10 and closed in E11 — not its own E-stage. D5 / Layer I stays Review.

2.3 Stage-by-stage — what actually runs

Contracts are HLD §8. This section only says which hop executes them. LLD: E1/E2 Done · E3/E4 Draft · E5–E11 backlog.

E1 Collect — admit bytes, do not bind

in: raw MELT / events / profiles · out: TelemetryEnvelope (ingest.v1)

  • Node: OTel receivers on the workload node (filelog, OTLP, hostmetrics, k8sevents). This is the required extra hop versus centralize-then-analyze.
  • SaaS: same E1 contract for sources that never hit a Node (GitHub, webhooks). Do not reuse a Node pipeline ID for those.
  • Not E1: k8s tag enrich, mask, Drain — those are E2 processors sitting on the same collector process.
  • Missing: nothing enters the pipeline.
E2 Identity / Normalize — stamp tenant + ci_id

in: TelemetryEnvelope · out: IdentifiedRecord overlay on the same ingest.v1 line

  • Node (primary): k8sattributes / resource / transform stamp tenant+ci_id+ci_type. Mask PII/secrets here so they never egress. Drain clusters repeats so volume drops before TLS.
  • SaaS: only the miss path — identity.status != resolved is queryable (FR-B1) and is not an E9/E11/ServiceOps target (D-E2-1).
  • Not E2: walking neighbors (E3), persisting the lake (E4), naming a leaf (E9).
  • Missing: joins across logs/metrics/traces collapse.
E3 Topology — Gateway assists; SaaS owns the graph

in: IdentifiedRecord + discovery cues · out: GraphSnapshot

  • Node: relationship cues only (pod→node, owner refs). Not a walkable graph.
  • Gateway (optional assist): OTLP consolidate, service graph, tail sample, dedup. Improves edge quality of call-edges before egress.
  • SaaS (canonical): persist/query GraphSnapshot. Authored schema is Grounded; live E3 discovery remains Design-level.
  • Do not equate E3 with Gateway. No Gateway still means E3 runs after ingest — just with thinner assist.
  • Missing: E9 cannot reason over propagation.
E4 Stores — SaaS ingest + the customer’s dest

in: IdentifiedRecord · out: time-sliced query surfaces by ci_id

  • Edge: buffers and backpressure. The Node is not a lake.
  • SaaS: ingest API routes the already-shaped stream to tenant-chosen dest(s). In Q1 that dest is E4 (destination-agnostic; Gate B picks the first two managed targets).
  • Missing: E6 door C and E10 have no history to query.
E5 Maintain — control plane pushes; agents execute

in: store/index metadata, discovery, change feeds · out: detect-ready freshness

  • SaaS: versioned collector config, canary, one-click rollback, tenancy policy, retention intent.
  • Node / Gateway: OpAMP (or equivalent) apply + heartbeat. Resource budgets so the agent does not fight the workload.
  • Missing: silent drift; RCA quality dies without a spectacular outage. Design-level — no dedicated lab.
E6 Detect — three doors, one stage

in: GraphSnapshot + store queries (door C) or shaped local stream (doors A/B) · out: Signal

  • Door A · Node Pipeline Trigger: fires on the shaped stream before egress. Fast, local, can be noisy. Shadow-mode vs door C until Gate C.
  • Door B · Gateway Pipeline Trigger: cluster-scope (needs Gateway). Absent if Gate A keeps Node-only.
  • Door C · org / platform monitor: evaluates after E4. Has history; slower; the door that still works when the edge is dark.
  • All three doors emit the same object: a Signal for a Detect class. None of them is a root-cause claim.
  • Negative Detect (symptom present, no Signal) is a valid outcome — not a defect to paper over.
  • Missing: no case opens automatically; operator can still seed at E8/E9.
E7 Curate — one seed (D3 Signed)

in: Signal + GraphSnapshot · out: CaseSeed

  • SaaS only for estate merge. Edge must not emit “the incident.”
  • Storm of door A + door C Signals → one seed with merge rationale. Multiple seeds only under explicit override.
  • Missing: operators drown; Detect looks broken when it is actually uncurated.
E8 Scope — lock time + neighborhood

in: CaseSeed · out: WorkingSet

  • SaaS: Tailor cut — k-hop on E3, time corridor on E4, env/version lock. This is what Clock B is allowed to see.
  • Edge cannot Scope: it does not hold the lake or the canonical graph.
  • Missing: E9/E10 run globally — noisy, expensive, unrankable.
E9 Localize — name the leaf

in: WorkingSet + GraphSnapshot + dest evidence · out: LeafClaim

  • SaaS / operator. Plug-in leaf rules: ERROR → deepest-error; SLOWDOWN → longest self-time; RESOURCE_CONTENTION → contended CI even if Detect was negative.
  • Optional Layer I may propose a leaf; it does not replace the operator path (D5 Review).
  • Missing: no actionable root-cause target.
E10 Identify — corroborate; Verify is decided here

in: LeafClaim + WorkingSet · out: EvidenceBundle

  • SaaS / operator: pull metrics / logs / traces from the dest inside the WorkingSet. This is where evidence tier (Verify) is judged.
  • Single-modality bundle allowed only with an explicit incompleteness flag.
  • Missing: a leaf exists but cannot be trusted or explained.
E11 Package — verdict card (D4 Signed)

in: EvidenceBundle · out: VerdictCard (+ optional incident / narrative)

  • SaaS: required verdict for close. Dest-native Problem / Bits / Issue is not our Package.
  • AI narrator is optional Layer I (D5 Review). Operator-only path always available (Gate D).
  • Missing: RCA stays an engineering object; the case never closes operationally.

6. Decision gates (interactive checkpoints)

  1. Gate A (end W3): keep Node-only for default path, or require Gateway for high-volume tenants.
  2. Gate B (end W7): pick default managed destination profile and supported fan-out matrix.
  3. Gate C (end W11): threshold ownership split between edge and platform monitors.
  4. Gate D (end W13): enable optional AI workflow for E9-E11 or keep operator-only mode by default.
