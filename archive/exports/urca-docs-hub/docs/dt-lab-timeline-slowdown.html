1) The defect (code-level, not a sleep flag)

Only dynatrace-rca-lab/inventory/app.py changed. Frontend and product were unchanged; they waited on inventory, so their response times rose as a cascade.

4) UI merge (Observed)

Operators first saw three Active Slowdown cards (P-260822 inventory · P-260821 frontend · P-260820 product), each Affected 1. Then Davis correlated them into one card: P-260820 with Affected 3. That is the operator-visible Curate/merge step — not a separate Dynatrace “Curate” product. Event ≠ Problem still holds: the API lists three Events under one Problem.

5) Why entity RCA was null

Same-time Events do not hard-forbid RCA, but Davis entity ranking often uses onset order (+ Smartscape). When all three SERVICE_SLOWDOWN Events share 15:05, there is no earlier leaf Event to mark rootCauseRelevant=true → rootCauseEntity stays null and the UI Root cause panel stays empty.

Why they aligned: every checkout is FE→product→inventory. The leaf CPU cost sits on the same request chain, so all three response-time series jump together. Contrast P-260814 (ERROR): inventory Event at 11:17, product/FE at 11:18 → inventory rootCauseRelevant=true → rootCauseEntity=inventory.

To chase leaf-first SLOWDOWN deliberately: inventory-only traffic first, then FE cascade — ./scripts/run_slowdown_staggered_rca.sh. That mimics P-260814’s temporal gap; it was started experimentally but the primary Observed analysis for this page remains P-260820 (same-bucket null RC).

6) Why code-level evidence is not on Problem analysis

Question: Even without entity RCA, shouldn’t analysis show app.py / line / function?
Answer (Observed): No — not on this Problem surface.

  1. Evidence type: Problem analysis here is built from Davis Events — SERVICE_SLOWDOWN metric breaches (“RT above threshold”). Those objects do not carry file/line.
  2. No exception: This defect returns HTTP 200. There is no stack for analysis to pin to a line (unlike KeyError on a span).
  3. Product split: Method/line/CPU hotspot lives under traces / code-level / profiling drill-downs. Dynatrace does not auto-promote that into the Problem Root cause / analysis block as a substitute when entity RCA is null.
Null entity RCA does not mean “code RCA is switched off.” Long Ok spans on inventory are still visible if you drill Problem → inventory → Distributed tracing. What is missing is an explicit code-line claim on the Problem analysis card.
