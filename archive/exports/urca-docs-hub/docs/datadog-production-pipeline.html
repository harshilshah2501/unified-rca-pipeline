It is not:

Fabric writes continuously first — Detect reads what is already written.

Not a Dynatrace dual-track: explorers stay separate; join is tags, not a shared entityId stamped onto a map and a lake. Backend is still not “three equal peer DBs” — Metrics timeseries ∥ Husky events (traces + logs). Cite: Introducing Husky · Husky query architecture.

Myths to drop: (1) platform lake = Grail — no; (2) Service Map is written in parallel like Smartscape — it is largely APM-derived; (3) Detect = only monitors — Watchdog is a second door; (4) Alert = Incident — stories can fire with zero Incidents (Observed (MCP)).

1.1 One join key for three explorers (tags)

In one sentence: Datadog stamps every metric, span, and log with the same keys (service, env, version, host, …). Those strings are how Related, monitors, and the flamegraph pivot. The three explorers never copy from each other — they all received the tags at write time.

Three rails, one job each
  • Metrics = what the number did (timeseries).
  • APM = what the call did (spans / flamegraph / inferred map).
  • Logs = what the line said (indexed events).
Without shared tags, “inventory” in a span, a metric, and a log are three different strings. Later steps cannot join them.

What “bind” means here: Tagging. Not a LUT to SERVICE-INV. Teaching filter: env:rca-lab-e3 + service:inventory + a version stamp.

Lab example (ERROR): inventory KeyError → HTTP 500 leaf / callers 502 · version:keyerror-20260810T072333Z.

Lab example (SLOWDOWN): inventory ledger-scan → HTTP 200 · ~9s leaf. Same Agent → tags → rails story; Detect and leaf evidence change.

Three steps · same bind, two Detect classes
① Arrive — dialects, no join yet

Span service:inventory · metric rca.inventory.stock.* · log stock.error / stock.ok — three products until tags match.

② Tag — stamp the join keys
raw records → service · env · version

Lab: DD_ENV=rca-lab-e3 on FE, product, and inventory.

③ Join — explorers share the filter

Same env/service/version on Metrics ∥ APM ∥ Logs. Service Map edges still come from spans, not from tags inventing topology.

5. Tag join — why it matters

Unique depth. Not a second mental model — §1 already said “join = tags.”

5.1 Where tags come from

  1. App / tracer — DD_SERVICE, DD_ENV, DD_VERSION (lab: datadog-rca-lab/docker-compose.yml).
  2. Agent — host tags, Docker/K8s auto-tags, datadog.yaml / DD_TAGS.
  3. APM enrichment — peers and status on spans as traces are processed.

Lab reminder: teaching filter is DD_ENV=rca-lab-e3 plus the per-run DD_VERSION on FE, product, and inventory. Retire rca-lab / rca-lab-e2 for ERROR teaching queries.

5.2 Two artifacts — do not conflate

Two artifacts — do not conflate
Tagging (this stage)

Telemetry stream → identity on each record

Service Map

APM discovery → call / peer edges

Tags do not invent the map; spans do. Map can lag traces — trust flamegraph / peer.hostname first on a fresh lab.

6.1 Pipeline insight

  • Join key is tags — evidence lives in APM / Metrics / Logs scoped by env:rca-lab-e3 / service / version.
  • Detect surfaces are not fused — Door A can Alert while Door B APM stays quiet (ERROR); both can stay quiet while Write is loud (SLOWDOWN).
  • Leaf rule changes with class — ERROR: deepest error. SLOWDOWN: longest self-time. Service Map chip is not the leaf.
  • Packaging stayed thin — Incident 0 in every Observed snapshot here.

8. Takeaway

  1. Describe Datadog as Datadog: Agent → Tagging → Metrics/APM/Logs → Monitors and Watchdog → flamegraph / Related → optional Bits/Incident.
  2. Service Map is largely APM-derived; product rails are separate explorers joined by tags; backend is Metrics timeseries ∥ Husky events.
  3. Host snapshot proved fabric + Watchdog; the lab proved microservice APM + Door A — still not a packaged Incident RCA card.
  4. Write ≠ Detect. SLOWDOWN can be loud in explorers with an empty foghorn.
