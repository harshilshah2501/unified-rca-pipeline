2) Detect reality (Observed)

Dynatrace’s native MONITORING_UNAVAILABLE severity is a platform-wide interruption (majority of OneAgents lose SaaS connectivity) — not a per-service OTLP gap. Intentional PG MONITORING_OFF + graceful systemctl stop oneagent did not auto-open OSI_UNEXPECTEDLY_UNAVAILABLE or severity MONITORING_UNAVAILABLE within the ~10–15 min lab window.

To still get a real Problems-API card for the inventory visibility-dark teaching path, we ingested a CUSTOM_ALERT on PROCESS_GROUP inventory via POST /api/v2/events/ingest. Davis packaged P-260826. Evidence type is CUSTOM_ALERT — not SERVICE_ERROR_RATE_INCREASED / SERVICE_SLOWDOWN.
