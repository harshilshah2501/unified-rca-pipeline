Teaching frame · DT vs DD

Observability 1.0 / 2.0 / 3.0 — evaluation criteria

Exact must-pass checks. Correlation alone is not 2.0. AI surfaces alone are not 3.0. Datadog and Dynatrace are hybrids — score layers, not brands.

A vendor “is 2.0” only if all four 2.0 criteria Pass. Same for 3.0. Any Partial/Fail → not a clean generation match.

1) Must-pass criteria

1.0

Three pillars

Separate stores + write-time questions + operator joins tabs.

  • C1 Pillars — metrics, logs, traces are separate first-class stores/tools
  • C2 Write-time — many metrics/questions fixed before the incident
  • C3 Manual join — correlation mostly after-the-fact (tags, IDs, tabs)
  • C4 Threshold Detect — alerts mainly static queries on series
2.0

Wide events

One rich event fabric; derive views later; join is built-in.

  • C1 Wide events — primary evidence is high-cardinality structured context
  • C2 Late binding — metrics/views can be derived after the fact
  • C3 Fabric join — correlation from event/entity model, not only tab pivots
  • C4 UX shape — event/entity-centric, not three peer pillar tabs
3.0 · emerging

AI assist

Anomaly Detect + named RCA package are default, not optional.

  • C1 Anomaly Detect — signal-aware / ML Detect is first-class
  • C2 Default package — named fault + evidence is the normal path
  • C3 Less babysitting — agents cut dashboard triage toil
  • C4 Cost selectivity (optional) — adaptive sampling / edge buffers when claimed

2) Why “they correlate” ≠ 2.0

1.0 already correlates (tags, trace IDs, dashboards). 2.0 requires the evidence model itself to be wide-event / late-bound / entity-joined — not only that an operator can pivot tabs after an alert.
