Inventory & catalog on the map

How agent inventory and CMDB / service catalog assertions show up in ObserveOps — not as separate forever-raw lakes, but as inputs to E2 Identity (Normalize) and edges on E3 Topology with auditable discovered_via provenance.

Hub: Our HLD · Fabric · Data shape journey · GRAPH_QNA G10–G11 · Discussion 04 (raw / LUT) · Example map (33 CIs)

What this page shows: two worked paths — inventory → runs_on edge (authoritative); catalog → depends_on edge (declared) — plus where each feeds the bind LUT vs map/. What we do not define yet: a ServiceNow-shaped CMDB record JSON or a dedicated inventory-scan wire format on ingest.v1. E1 Collect does not ingest CMDB tickets this pass; catalog and inventory reach us through sync jobs and agents that update the LUT and topology writers.

Three sources (one axis — not the same as LUT miss policy)

Source classWho owns the fact?Typical edgeevidence_typePrimary ObserveOps sink
Inventory System of record (agent cgroup, Kubernetes API, vCenter, mount table) runs_on, hosted_on, mounts authoritative E3 edge + often E2 LUT row (hostname → ci_id)
Catalog / CMDB Human or config asserted (service catalog, Terraform, CMDB import) depends_on, part_of, member_of declared E3 edge + E2 LUT alias rows on sync
Telemetry Live observation (spans, logs, eBPF peers) communicates_with corroborating E3 candidate edge; weak alone for identity.status = resolved

E2 LUT vs E3 map/ — where each source lands

Readers confuse “inventory” with “the bind table.” They are related but not the same object:

Source updateE2 Identity (Normalize) — bind LUTE3 Topology — map/
Agent sees JVM on host May add linux-server-app-01 → ci_id and cgroup alias rows so metric lines bind Writes runs_on edge with evidence_type: authoritative
Catalog sync: checkout depends on payments-db May add service-name aliases → stable ci_id for both ends Writes depends_on edge with evidence_type: declared
Span shows checkout → inventory-api Usually does not alone flip identity.status = resolved (D-E2-1) Writes communicates_with as corroborating; short valid_to until inventory confirms
LUT miss on a metric line (Case 2) Hold raw in quarantine; promote to resolved when inventory or catalog sync fills the LUT No production edge/sketch write until resolved
One line for the meeting: inventory and catalog are who owns or asserts a relationship. Auto-create / Orphan / Soft-match (Discussion 04 · Q3) are what to do when a name does not bind to a CI yet — not a 1:1 map onto evidence_type. See GRAPH_QNA G11.
