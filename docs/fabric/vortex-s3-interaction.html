Who “agent” is (and is not)

Motadata Pillar C · Rust ReAct agent

In Motadata materials, agent means the optional diagnose loop (Layer I / Interpret): observe case → tools against a bounded evidence set → propose. It is not Collect, Topology, E4 writers, or “any HTTP caller.” On our pipeline the same rule is broader: the whole diagnose path (retrieval, Localize, Identify, and optional ReAct) must not open S3 or hop-scan Vortex as a dump. Operator E9–E11 must work with ReAct off.

Retrieval ──► WorkingSet ──► Localize / Identify └──► optional Rust ReAct (tools only inside that budget)

Three interaction patterns

1 · Hot write → Vortex; cold spill → S3

Fresh rows from the pipeline land in Vortex first (both rooms). As windows age past a retention threshold, Vortex spills those rows to S3 as compressed columnar files. Hot working set stays small; S3 holds history cheaply.

Pipeline writer ──► Vortex (hot, queryable) ──age-out──► S3 (cold, durable)

2 · Federated read-back: Vortex pulls from S3 on demand

When Retrieval asks for data older than the hot window, Vortex scans the relevant S3 partitions and merges them into the response. Diagnose never talks to S3 directly — Vortex is the single query surface for this dest profile.

Retrieval ──query──► Vortex ──scan──► S3 ──merge──► Vortex ──WorkingSet──► Localize / opt. ReAct

3 · Immutable archive: S3 is the cold system of record

Once a GraphSnapshot version or sketch batch is on S3, it is immutable. Topology change → new snapshot version. Sketch correction → new row with later write time. S3 is durable history; Vortex is the fast query cache on top.

What each component is not

Vortex is not

Not the pipeline (Collect / Identity / Topology write into it). Not the only E4 dest forever. Not the ReAct agent — Retrieval queries Vortex; the optional agent only sees a WorkingSet.

S3 is not

Not a query engine. Not opened by Retrieval, Localize, or the Rust ReAct agent. Not mandatory in lab (file dest is fine). Not a second source of truth — colder copies of the same rows.

E4 fan-out is not

Not Vortex itself. E4 Stores is the write job; fan-out is which product receives the rows. Vortex/S3 is one answer among file dest, Motadata store, or another lake.

Key rule: Rooms = content type. Vortex / S3 = temperature for those rows on this dest. Diagnose path = Retrieval → WorkingSet (optional ReAct is a client of that, not of S3).
