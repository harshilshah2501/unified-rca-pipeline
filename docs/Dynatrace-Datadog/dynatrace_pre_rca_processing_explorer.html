The Two-Stage Correlation Engine

Decoupling statistical co-occurrence from topological graph directionality.

1. Signal Correlation

TIME DOMAIN

Question: "What observations changed together?"

  • Computes relative deviation scores ($z$-scores) for metrics across window $t_{anchor} \pm \Delta t$.
  • Normalizes heterogenous alert formats into unified time buckets.
  • Calculates statistical cross-correlation over sliding time windows.
Input: Raw M.E.L.T Chunk & Alerts
Output: Co-occurring Anomaly Clusters

2. Causal Correlation

TOPOLOGY DOMAIN

Question: "Which observation caused the others?"

  • Projects correlated signal clusters onto the active Smartscape sub-graph.
  • Evaluates directed call paths (Application $\rightarrow$ Service $\rightarrow$ Process $\rightarrow$ Host).
  • Applies temporal directionality (Cause must precede Effect in time).
Input: Anomaly Clusters + Smartscape Graph
Output: Directed Causal Propagation Chain

Ingestion & OpenPipeline Stream Processing

OpenPipeline modifies, validates, and enriches telemetry in-flight before writing to Grail.

⚡ OneAgent Native Ingestion

Automatic instrumentation with deep process metadata. Enriches with host groups and Kubernetes cluster context automatically.

🌐 OpenTelemetry (OTLP)

Standards-based ingestion via OTLP. Requires resource attribute mappings (service.name, k8s.pod.name) for Smartscape resolution.

"Attribute values exceeding 4,096 characters are automatically truncated during OpenPipeline execution to preserve memory and schema performance."
