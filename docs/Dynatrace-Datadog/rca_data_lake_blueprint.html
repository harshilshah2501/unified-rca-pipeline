The RCA Data
Pre-Processing Puzzle

The problem, in one sentence: given noisy, high-volume, multi-modal telemetry and a shifting estate, automatically (or assistively) answer what is wrong, where the fault is, and — when justified — why, with an evidence trail an SRE can trust.

Market shorthand: Step 1 "where" ≈ Detect → Localize (vendors automate this well). Step 2 "what happened there" ≈ Identify (+ Verify) — deep path-diff automation is still thin. white space

Raw production data is huge, heterogeneous, non-stationary (deploys change topology), and identity-unstable (pods churn, monitors rename). So the real systems problem isn't "store everything" — it's:

Create an entity-keyed, time-aligned store; then, per incident, tailor a small AI-ready working set (seed + neighborhood + corridor) that Localize/Identify can reason over.

How competitors tackle it

Three philosophies from public product framing + vendor notes — self-reported where noted. All of them scope before they reason: none feeds the whole retention window into one model per ticket.
SHARED PATTERN — ALL SERIOUS PLAYERS
  • Agents + continuous discovery → entity universe
  • Detect / Watchdog / Davis events → incident seed
  • Entity / service / Smartscape-style graph → where to relate signals
  • Incident-scoped pull of metrics/logs/traces near the seed (not the full lake)
  • Rank or pick a culprit → UI + optional AI narrative
  • Human Step-2 for deep method/path "why" (often) gap

Open questions & takeaway

What's still unresolved, and the five-point summary of where this stands.
  • 1Motadata sample: measured % in classes A–D?
  • 2Default corridor: ±15 min vs ±2 h vs change-aware?
  • 3When is "no logs" an acceptable product claim?
  • 4Incident lead example: ecom-numa vs UC appendix?
  • 5Detect demo: stream → threshold → seed, live?
  • 6Minimum trace sampling for class-D Identify under cost caps?
  • 7Where do we deliberately not copy Dynatrace causal marketing vs Datadog Watchdog branding?
  • Problem = joinable multi-modal estate + a Detect seed + scoped reasoning — not "bigger lake."
  • Pains = volume, identity, stale topology, bad seeds, symptom bias, modality gaps, and a Step-2 automation hole.
  • Dynatrace = topology-first + causal claim. Datadog = platform lake + statistical/Watchdog Localize + multimodal pivot. Both scope before they reason.
  • Our bet = shared Detect, typed-topology Localize, honest Verify tiers, a multimodal report bar, and the fused path-Identify white space.
  • The §5-style percentiles stay priors until ticket-sampled.
