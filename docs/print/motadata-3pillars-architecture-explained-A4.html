1 · Pillar A · statistics

T-Digest + explicit buckets + seasonal baselines

One job, three parts: keep a mergeable percentile, keep a cheap histogram, keep a usual range for this hour of this weekday. Together they answer “is this weird?” without replaying weeks of raw samples.

What

A small, stored summary of how a metric usually behaves — not the raw time series. T-Digest ≈ percentiles. Buckets ≈ histogram. Seasonal baseline ≈ “normal for this slot in the week.”

Why

Weeks of samples cannot be scanned on every alert. Monday 9am traffic is not an outage. You need mergeable summaries and a calendar-aware expected range, or Detect lies.

How

Window samples (1m/5m/1h/1d). Fold into a T-Digest (mergeable p50/p95/p99) and fixed buckets (deterministic bins). Key the expected range by hour-of-day + day-of-week. Query is a key lookup, not a raw scan. “O(1)” means O(1) in sample count — still a bounded index read.

Example. Checkout p95 = 180 ms. Tuesday 14:00 baseline p95 ≈ 200 ms → normal. Sunday 02:00 baseline p95 ≈ 40 ms → 180 ms is abnormal. Same number; different season_key.

Why both T-Digest and buckets? Percentiles merge cleanly across windows and entities. Buckets make histogram queries and alert rules deterministic and cheap. Seasonal baselines stop business cycles from looking like faults.

2 · Pillar B · map

Graph builder — entities + edges + changes

Continuously maintain a typed picture of the estate: what exists, how it connects, and what recently changed. This is an RCA map, not a generic enterprise knowledge graph.

What

A living map: typed things (Service, Host, Pod, Database, Change, Alert, …) plus typed links, plus change facts. Time-bounded: edges expire (valid_from / valid_to).

Why

A detector without a map produces an alert. A detector with a map can say which neighbor sits under the symptom, whether a deploy landed, and how sure we are that the link is real.

How

Builders upsert entities and edges from telemetry and discovery. Changes are first-class nodes, not log lines you grep later. Traversal: Incident → service → deps → recent changes → abnormal metrics → traces/log patterns → candidate leaves.

Example. Pain shows on checkout-api. Walk CALLS → checkout-db. A CHANGED_BY deploy landed 12 minutes ago on the db. API p95 is high; db p95 is worse. The leaf candidate is the database, not the API.

3 · the lake · Pillars A and B land here

Vortex + S3 — historical observability + knowledge graph

Two rooms in one warehouse. Room 1 holds compact history (sketches, and whatever raw you still keep). Room 2 holds the typed map. Vortex/S3 is durability. It is not the agent, and it is not Detect.

What

The long-lived store. “Historical observability” = queryable past (especially sketches). “Knowledge graph” = who-is-connected, versioned. Same entity_id namespace in both rooms.

Why

Builders are useless if the result evaporates. RCA also must not mutate history in place — mergeable / immutable analytical state, no expensive historical UPDATE.

How

Percentile engine and graph builder write in parallel after identity exists. S3 holds cold/large objects; Vortex is the analytical engine on top. The agent never opens this as a dump — it goes through retrieval.

4 · P2 Scope · the budget in front of the lake

RCA retrieval layer — baseline + graph + events + changes

A funnel, not a search engine. When a case opens, fetch only what diagnose is allowed to see: the usual range, the neighborhood, the events, the recent changes — inside a budget.

What

A bounded index in front of Vortex: “give me these four evidence kinds, for this seed, under these limits.” In our language that object is the WorkingSet.

Why

Unscoped RCA walks the estate and hallucinates. Cost, latency, and wrong neighbors all explode. The PDF’s production principle: retrieval bounded by time, entity, hop count, and evidence budget.

How

Start from the curated seed (not from the raw alert storm). Expand k hops on the graph. Pull matching baselines, events, and changes inside the time window. Stop when the budget is spent. Then Localize.

Example. Seed = checkout-api at 14:02. Budget: 30 minutes, 2 hops, 40 evidence items. You get the API, its db, the last deploy, p95 vs Tuesday baseline — not the whole cluster.

5 · Pillar C · optional Layer I

Rust RCA agent — bounded ReAct execution

ReAct means reason, then act, then reason again — but every act is a typed tool with a timeout, a permission, and an audit line. The model proposes. A policy engine authorizes. The model never owns the switch.

What

A production ReAct loop in Rust: observe the case, retrieve A+B through the budget, correlate, score hypotheses, validate with evidence, then propose an action. Tools are structs + serde, not free-form HTTP.

Why

The differentiator is not “LLM + observability.” Baselines and the graph constrain reasoning; policy constrains action. An unconstrained chat over Vortex is not RCA.

How

Each tool: typed input, capability, timeout, retry, risk class, dry-run for writes, audit event, idempotency key, cancellation. Parallel investigation is bounded (JoinSet). Failures are Result. Rust, not Python/GIL, for the hot path.

Example. Hypothesis: “db saturation after deploy.” Validate by get_metric_baseline() + query_graph() + get_recent_changes(). If evidence disagrees, drop it. If it holds, Package a verdict. Ticket only if policy allows. Never let the model fire execute_remediation() itself.

Which phase owns each pillar

A pillar is not a phase. A and B are always-on P1 stores. P2/P3 only read them. C is Clock B (diagnose/close), optional Layer I.

Recommended implementation order

Do not ship A → B → C as three products. A and B are parallel P1 writers after E2 keys exist. C is last and opt-in (Gate D / D5 Review).

So: identity → stores (A+B) → detect/curate/scope → deterministic RCA → optional agent.

What to take vs what not to copy

Take: mergeable percentile sketches as an E4 modality; typed RCA graph with valid_from/to and confidence as E3; bounded retrieval as E8; hypothesis-plus-evidence language for E10; LLM never owns authorization if Layer I ships.
Do not copy: skipping Node E1–E2; treating NATS+Vortex as the whole product; folding Curate into the agent; making ReAct the default Package path; calling ITSM or remediation Collect. Do not flip D5 because the PDF is agentic.
