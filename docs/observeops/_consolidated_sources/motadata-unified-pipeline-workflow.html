Motadata · ObserveOps · one pipeline

Unified pipeline — end-to-end workflow

One Motadata ObserveOps pipeline with eleven stages: always-on fabric (Collect through Maintain), then per-case triage and diagnose (Detect through Package). After Identity, topology and stores write in parallel into map/ and history/; Scope read-joins both into a WorkingSet. This page teaches that story with a clean poster layout — the content is our HLD, not a vendor analogy remodel.

At E8 Scope, the WorkingSet is a read-join: neighbors from map/ plus sketches from history/ for those CIs — same tenant + ci_id namespace.

Follow the map (usual)

Localize walks authoritative edges (depends_on, runs_on, …) toward the leaf the Detect class expects. Identify attaches sketch percentiles and edge provenance.

Evidence can override

If sketches or corroborating edges contradict the first walk, Identify lowers confidence or revises the leaf — fabric stays; the case objects change.

E6 Detect

LaneContent
InputGraphSnapshot (which CIs / detectors apply) + store/sketch queries keyed by ci_id
ProcessingEvaluate Detect-class rule per CI (threshold / anomaly score). CI tip = the ci_id whose series breached. t0 = observation / event time of that decision.
OutputSignal — fault class + CI tip + t0 (no root claim)
