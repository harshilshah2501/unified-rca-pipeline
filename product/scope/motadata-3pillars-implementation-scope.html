3. What we expect from E1 (not our build)

E1 admits telemetry. It does not bind, detect, or merge. Contract: LLD-E1.

Send metrics, logs/events, optional traces, topology cues. Do not send tickets or CMDB this pass.

Collect bridge (corpus / lab) emits UTF-8 JSONL as ingest.v1. After E2, Motadata writers prefer writer_stream.v1 blocks (see regulator link above).

{
  "schema_version": "ingest.v1",
  "ts": "2026-08-19T12:00:00Z",
  "tenant": "default",
  "ci_id": "checkout-api",
  "ci_type": "Service",
  "fact_kind": "metric_sample",
  "name": "request.p95_latency_ms",
  "value": 1450.0,
  "labels": { "source": "lab-node" }
}

Legacy Collect fact_kind (bridge): metric_sample, anomaly, event, trace_span, topo_update. Reserved (do not emit): change_event, cmdb_sync, ticket. Motadata writers admit by optional-block presence, not this enum.

Preferred lab folder: datasets/ingest_samples/<suite>/<incident_id>/stream.jsonl + topology.json + optional ground_truth.json.

4. What we expect from E2 (not our build)

"identity": {

Only resolved may be an E9 leaf or ticket CI (D-E2-1). Pillars A and B write resolved rows only. Need a bind strategy: topology lookup or Motadata ci_bind.json. One identity namespace for sketches and graph.
